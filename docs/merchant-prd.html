路由 & 页面地图

Merchant 端 7 个页面全部 P0，均需登录（除 login）。布局使用桌面端 Sidebar，左侧固定导航，右侧内容区。

路由 页面名称 优先级 鉴权 说明
/merchant/login 商家登录 P0 无需 邮箱 + 密码；首次登录强制修改密码
/merchant/dashboard 工作台 P0 需登录 数据概览、待处理提醒、快捷入口、配置完整度引导
/merchant/products 我的商品 P0 需登录 已选品列表、价格管理、上下架操作
/merchant/products/catalog 浏览商品母库 P0 需登录 按品类/关键词浏览母库，选品添加到本店
/merchant/services 维修服务管理 P0 需登录 从平台维修目录选择本店提供的服务，设置定价
/merchant/bookings 预约管理 P0 需登录 预约列表（待确认/已确认/已完成）、接受/拒绝/完成核销
/merchant/settings 门店设置 P0 需登录 基础信息、营业时间配置、修改密码
布局说明：未登录时所有 /merchant/*（除 login）重定向到登录页，保留原始 next 参数。侧边栏导航项：工作台 / 我的商品 / 维修服务 / 预约管理 / 门店设置。

登录 & 首次初始化配置

商家通过邮箱密码登录，首次登录强制修改密码后才能进入工作台。

3.1 登录页 /merchant/login

页面功能
邮箱输入type=email，自动 trim/lowercase
密码输入type=password，眼睛图标切换明文
登录按钮loading 状态防重复提交
错误提示邮箱不存在/密码错误/账号停用，统一显示"邮箱或密码错误"（安全）
首次登录后端检测 mustChangePassword=true，响应中返回标记
交互逻辑
登录成功写 HttpOnly Cookie（merchantSession），跳转 /merchant/dashboard
首次登录跳转 /merchant/settings?tab=security&firstLogin=1，强制修改密码，不允许跳过
会话过期受保护页面返回 401 时，重定向回登录页，保留原始 next 路径

3.2 Onboarding 引导（工作台顶部进度条）

首次完成登录后，工作台顶部展示配置进度条（3 步）：① 完善店铺信息（店名/地址/Eircode/电话）→ ② 设置营业时间（7 天每天开关门）→ ③ 选择至少 1 件商品或 1 项维修服务上架。3 步全部完成前，进度条持续显示（不可关闭）。完成后自动消失，门店进入"营业"状态。
步骤完成条件跳转目标
① 完善店铺信息 name + address + eircode + phone 均不为空 /merchant/settings?tab=info
② 设置营业时间 MerchantHours 表中该门店至少有 1 天 isClosed=false /merchant/settings?tab=hours
③ 上架商品或服务 MerchantProduct 或 MerchantService 中有至少 1 条 isActive=true /merchant/products/catalog

数据库 Schema — 新增 3 张表

需要新建 Prisma migration。执行前确认 prisma/schema.prisma 中 Merchant 表已存在。

迁移命令：npx prisma migrate dev --name add-merchant-portal-tables，然后 npx prisma generate

MerchantProduct — 门店选品

model MerchantProduct {
  id          Int      @id @default(autoincrement())
  merchantId  Int
  merchant    Merchant @relation(fields: [merchantId], references: [id], onDelete: Cascade)
  productId   Int
  product     Product  @relation(fields: [productId], references: [id], onDelete: Cascade)
  price       Decimal  @db.Decimal(10, 2)   // 本店实际售价（€）
  isActive    Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@unique([merchantId, productId])   // 同一门店不能重复选同一商品
  @@index([merchantId])
  @@index([productId])
}

MerchantService — 门店维修服务定价

model MerchantService {
  id              Int           @id @default(autoincrement())
  merchantId      Int
  merchant        Merchant      @relation(fields: [merchantId], references: [id], onDelete: Cascade)
  repairServiceId Int
  repairService   RepairService @relation(fields: [repairServiceId], references: [id], onDelete: Cascade)
  price           Decimal       @db.Decimal(10, 2)   // 本店报价（€）
  isActive        Boolean       @default(true)
  createdAt       DateTime      @default(now())
  updatedAt       DateTime      @updatedAt

  @@unique([merchantId, repairServiceId])
  @@index([merchantId])
  @@index([repairServiceId])
}

MerchantHours — 营业时间

model MerchantHours {
  id          Int      @id @default(autoincrement())
  merchantId  Int
  merchant    Merchant @relation(fields: [merchantId], references: [id], onDelete: Cascade)
  dayOfWeek   Int      // 0=周日, 1=周一 ... 6=周六
  openTime    String?  // "09:00"（isClosed=true 时为 null）
  closeTime   String?  // "18:00"
  isClosed    Boolean  @default(false)

  @@unique([merchantId, dayOfWeek])
  @@index([merchantId])
}

鉴权设计

Merchant Session 与 Admin Session 完全独立，使用不同 Cookie 名和不同 secret，互不干扰。

Session 机制
方案HttpOnly Cookie（与 Admin 端相同方案）
Cookie 名merchantSession（区别于 adminSession）
过期时间7 天，访问时自动续期
内容{ merchantId: number, email: string }（加密）
实现位置src/lib/merchant-auth.ts
requireMerchantSession()
// src/lib/merchant-auth.ts
export async function requireMerchantSession() {
  const session = await getMerchantSession();
  if (!session) {
    throw new Response(
      JSON.stringify({ error: "未登录" }),
      { status: 401 }
    );
  }
  return session; // { merchantId, email }
}
隔离原则：Admin 登录不赋予商家权限，反之亦然。每个受保护的 API 路由第一行调用 requireMerchantSession()。用管理员 Cookie 访问 /api/merchant/me 应返回 401。

开发任务清单（按顺序执行）

分 6 批，按依赖顺序执行。每批完成后验证再进入下一批。

第一批：基础设施（先做，其余依赖它）

  • Prisma schema 新增 MerchantProduct / MerchantService / MerchantHours 3 张表，跑 migrate dev
  • Merchant 表新增 mustChangePassword Boolean @default(true) 字段
  • 创建 src/lib/merchant-auth.ts（getSession / requireSession / setSession / clearSession）
  • 创建 src/app/merchant/layout.tsx（Sidebar 导航 + 鉴权 redirect）
  • 创建 src/components/merchant/MerchantSidebar.tsx

第二批：认证流程

  • API: POST /api/merchant/auth/login（bcrypt 校验 + 写 Cookie）
  • API: POST /api/merchant/auth/logout（清 Cookie）
  • API: POST /api/merchant/auth/change-password
  • 页面: /merchant/login（表单 + 错误提示）
  • 首次登录检测：login API 若 mustChangePassword=true，响应中返回 requirePasswordChange: true

第三批：门店设置（Onboarding 必须）

  • API: GET /api/merchant/me
  • API: PATCH /api/merchant/me（含 Eircode geocode 调用）
  • API: GET + PUT /api/merchant/hours
  • 页面: /merchant/settings（3 个 Tab：店铺信息 / 营业时间 / 账号安全）

第四批：商品选品

  • API: GET /api/merchant/catalog（母库浏览，含 isSelected 标记）
  • API: GET/POST /api/merchant/products
  • API: PATCH/DELETE /api/merchant/products/[id]
  • 页面: /merchant/products/catalog（品类侧边栏 + 商品网格 + 添加弹窗）
  • 页面: /merchant/products（已选品列表 + 价格内联编辑 + 上下架切换）

第五批：维修服务配置

  • API: GET /api/merchant/repair-catalog（4 层级联浏览，含 isSelected）
  • API: GET/POST /api/merchant/services
  • API: PATCH/DELETE /api/merchant/services/[id]
  • 页面: /merchant/services（Tab 按品类分组 + 服务列表 + 添加弹窗）

第六批：工作台 + 预约

  • API: GET /api/merchant/dashboard
  • 页面: /merchant/dashboard（Onboarding 进度条 + 统计卡片 + 快捷入口）
  • API: GET /api/merchant/bookings（含空状态，RepairBooking 表建好后联调）
  • API: PATCH /api/merchant/bookings/[id]（accept/decline/complete）
  • 页面: /merchant/bookings（状态 Tab + 预约卡片 + 操作按钮）

验收标准（全部通过才算完成）

  • Admin 创建商家账号后，商家能用邮箱密码登录
  • 首次登录强制修改密码，改完后才能进工作台
  • 完成 Onboarding 3 步（信息/时间/选品），进度条消失
  • 从母库选了商品并设价后，能在"我的商品"看到，且价格不能低于平台参考最低价
  • 从维修目录选了维修服务并设价后，能在"维修服务"看到
  • 修改营业时间后，GET /api/merchant/hours 返回更新后的数据
  • 未登录状态访问 /merchant/dashboard → 302 → /merchant/login
  • 用管理员 Cookie 访问 /api/merchant/me → 401（Session 隔离）
