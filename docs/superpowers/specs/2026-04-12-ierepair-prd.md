> 版本：1.0  
> 日期：2026-04-12  
> 状态：已确认

---

## 概述

IERepair 是一个面向爱尔兰手机维修行业的三端 SaaS 平台，由总部统一运营，支持多个加盟门店接入。平台提供：

- **C 端门户**：消费者通过总部或门店官网查找维修服务、购买配件、在线预约
- **门店管理端**：门店老板管理网站内容、产品上架、预约订单、财务报表
- **总部管理端**：总部管理产品母库、门店账号、全平台订单与财务提成

技术架构采用 **Next.js 单仓库多租户**方案，三端共存一个代码库，通过 hostname 中间件识别当前租户（门店）。

## 一、C 端（消费者门户）

### 1.1 多租户路由

| 场景 | URL 形式 | 展示内容 |
|------|----------|----------|
| 门店子域名 | `store1.ierepair.ie` | 该门店品牌、产品、维修服务 |
| 总部官网 | `ierepair.ie` | 所有门店入口 + 全平台搜索 |
| 门店自定义域名 | `repairs.johnsphone.ie` | 同子域名，通过 hostname 中间件映射 |

- 门店可申请绑定自定义域名，由总部在 Admin 后台配置
- 门店官网只展示该门店已上架的商品和服务
- 总部官网展示全平台内容，支持按门店筛选

### 1.2 浏览与搜索

**维修服务索引（三级）：**
1. 手机品牌（Apple / Samsung / Huawei…）
2. 手机型号（iPhone 16 / Galaxy S24…）
3. 问题类型（换屏 / 换电池 / 进水维修…）

**配件浏览：**
- 按品类筛选：手机壳、钢化膜、充电线、耳机、其他配件
- 支持品牌 / 型号兼容性筛选

**搜索：**
- 关键词搜索（型号名、问题描述、配件名称）
- 搜索结果区分维修服务和实体配件

### 1.3 维修预约流程

```
选择维修服务 → 选择门店（总部官网需选，门店官网自动确定）
→ 选择预约时间 → 填写联系信息（姓名 / 手机号 / 邮箱）
→ 可选：支付在线定金 → 收到确认邮件
```

**定金支付：**
- 消费者可选择是否在线支付定金（定金金额由门店在后台设置，默认可为 0）
- 在线定金由平台收取，维修完成后扣除 10% 提成后结算给门店
- 未支付定金的预约仍可提交，总部通过定期对账向门店结算提成

**时间选择：**
- 门店在管理端设置可预约时间段
- C 端展示可用时间供消费者选择

### 1.4 配件购买流程

```
浏览配件 → 加入购物车 → 选择配送方式（邮寄 / 门店自提）
→ 填写配送信息 → 在线支付全额 → 收到确认邮件
```

- 配件收入 100% 归门店，平台不收提成
- 邮寄需门店填写运费；自提无运费

### 1.5 用户账号

- **游客模式（主）**：无需注册，留邮箱 + 手机号即可完成预约/下单
- **注册账号（可选）**：注册后可查看历史维修记录和配件订单
- 注册支持邮箱 + 密码，后续可扩展 Google 登录

### 1.6 通知

| 触发事件 | 通知方式 | 接收方 |
|----------|----------|--------|
| 预约提交成功 | 邮件 | 消费者 |
| 门店确认预约 | 邮件 | 消费者 |
| 门店拒绝预约 | 邮件（含原因） | 消费者 |
| 维修完成，可取件 | 邮件 | 消费者 |
| 配件已发货 | 邮件（含物流单号） | 消费者 |
| 新预约到达 | 邮件 | 门店 |

## 二、门店管理端（Merchant Portal）

入口：`ierepair.ie/merchant` 或 `merchant.ierepair.ie`

### 2.1 账号与权限

- 总部在 Admin 后台创建门店账号（见第三节 3.2）
- 门店收到邮件后首次登录并修改密码
- 每个门店账号数据严格隔离，只能看到自己门店的数据
- 预留多账号支持（如门店老板 + 员工），当前阶段每店一账号

### 2.2 网站内容管理

门店可编辑自己官网的展示内容：

| 可编辑项 | 说明 |
|----------|------|
| 店名 / Logo | 展示在门店官网顶部 |
| 门店地址 | 展示 + 链接至 Google Maps |
| 营业时间 | 按星期几设置开放时间段 |
| 门店简介 | 富文本，最多 500 字 |
| 联系方式 | 电话、邮箱、WhatsApp |
| 门店图片 | 最多 10 张（门面照、内部环境） |
| 首页 Banner | 自定义标题文字和副标题 |

### 2.3 产品与服务管理

**从母库选品：**
- 浏览总部维护的维修服务和配件目录
- 勾选要上架到本店的项目
- 已勾选项目显示在"我的产品"列表

**独立定价：**
- 每个上架项目可以设置本店售价（覆盖总部建议价）
- 维修服务额外可设置定金金额（0 表示不需定金）
- 价格修改实时生效

**上下架控制：**
- 支持单个或批量上架 / 下架
- 下架不删除数据，可随时恢复
- 已下架产品在 C 端不可见，但不影响历史订单记录

### 2.4 预约时间管理

- 设置每周可预约的时间段（如：周一至周六 09:00–18:00）
- 设置单个时间段最大同时预约数
- 可临时关闭特定日期（节假日、装修等）

### 2.5 维修预约订单管理

**订单状态流转：**
```
待确认 → 已确认 → 进行中 → 已完成
              ↘ 已取消（门店拒绝或客户取消）
```

**操作权限：**

| 操作 | 说明 |
|------|------|
| 确认预约 | 系统自动发邮件通知客户 |
| 拒绝预约 | 需填写原因，自动通知客户，退还已付定金 |
| 标记进行中 | 客户已到店，开始维修 |
| 标记完成 | 录入实收金额（全额或尾款） |
| 备注 | 内部备注，客户不可见 |

**列表视图：**
- 默认显示今日预约
- 支持按状态 / 日期 / 客户姓名筛选
- 显示客户联系方式、设备型号、维修项目、定金状态

### 2.6 配件订单管理

**订单状态流转：**
```
待处理 → 已发货（填快递单号）→ 已完成
       → 已备货（自提）→ 已自提 → 已完成
```

- 支持按状态筛选
- 查看买家配送信息和商品明细
- 导出订单列表 CSV

### 2.7 财务报表

**月度报表内容：**

| 指标 | 说明 |
|------|------|
| 维修收入合计 | 本月已完成维修单总额 |
| 配件收入合计 | 本月已完成配件订单总额 |
| 平台提成（维修） | 维修收入 × 10% |
| 门店实收 | 维修收入 × 90% + 配件收入 |
| 在线定金收入 | 平台已结算的定金金额 |
| 待结算提成 | 线下收款订单对应的应付提成 |

- 支持按月份切换查看
- 导出 CSV

## 三、总部管理端（Admin Portal）

入口：`ierepair.ie/admin` 或 `admin.ierepair.ie`

### 3.1 产品母库管理

**维修服务目录：**

| 字段 | 说明 |
|------|------|
| 服务名称 | 如"换屏"、"换电池" |
| 适用品牌 | 多选 |
| 适用型号 | 多选（关联品牌） |
| 问题类型 | 如"屏幕损坏"、"电池续航差" |
| 建议价格 | 门店可覆盖 |
| 预计维修时长 | 如 "1–2 小时" |
| 状态 | 上架 / 下架 |

**配件目录：**

| 字段 | 说明 |
|------|------|
| 配件名称 | |
| 品类 | 手机壳 / 钢化膜 / 充电线 / 耳机 / 其他 |
| 适用品牌 / 型号 | 可选 |
| 建议价格 | |
| 图片 | 最多 5 张 |
| 状态 | 上架 / 下架 |

**操作：**
- 新增 / 编辑 / 删除
- 批量导入（CSV 模板下载 + 上传）
- 下架后所有门店自动隐藏该项目（不影响历史订单）

### 3.2 门店管理

**创建门店：**

| 字段 | 说明 |
|------|------|
| 店名 | |
| 子域名 | 如 `fitzwilliam`（即 `fitzwilliam.ierepair.ie`） |
| 联系人姓名 | |
| 联系邮箱 | 用于发送初始登录凭证 |
| 联系电话 | |
| 地址 | |
| 提成比例 | 当前固定 10%，字段预留可配置 |

**门店列表操作：**

| 操作 | 说明 |
|------|------|
| 编辑信息 | 修改门店基本资料 |
| 重置密码 | 发送重置邮件给门店联系邮箱 |
| 停用 / 启用 | 停用后门店无法登录，官网显示"暂停服务" |
| 绑定自定义域名 | 填写域名，平台配置 hostname 映射 |
| 查看上架产品 | 只读，查看该门店已上架哪些产品 |

### 3.3 全平台预约订单总览

- 查看全平台所有维修预约
- 筛选条件：门店 / 日期范围 / 订单状态 / 是否已付定金
- 只读视图，不可代替门店操作
- 导出 CSV

### 3.4 财务与提成管理

**提成计算规则：**
- 仅维修单收取提成，配件订单不收
- 提成 = 已完成维修单实收金额 × 10%
- 在线定金部分由平台直接持有，维修完成后结算
- 线下收款部分通过对账流程结算

**对账流程：**
```
门店在管理端申报线下收款（填写维修单号 + 实收金额）
→ 总部审核确认
→ 系统生成该笔提成账单
→ 总部向门店开具服务发票，门店付款
→ 账单标记为已结算
```

**报表功能：**

| 报表 | 说明 |
|------|------|
| 全平台收入汇总 | 按月，维修 / 配件 / 在线定金分列 |
| 门店提成明细 | 按门店 + 月份，列出每笔维修单提成 |
| 待结算账单 | 线下收款已申报、待总部确认的账单 |
| 历史结算记录 | 已完成结算的历史账单 |

- 导出 PDF（对账单）/ CSV（原始数据）

### 3.5 数据概览 Dashboard

| 指标卡 | 说明 |
|--------|------|
| 今日全平台预约数 | |
| 今日全平台收入 | 在线支付部分 |
| 本月活跃门店数 | 有完成订单的门店 |
| 本月平台提成总额 | |

**图表：**
- 各门店本月业绩排名（柱状图）
- 热门维修项目 Top 10（条形图）
- 近 30 天全平台预约趋势（折线图）

## 四、跨端数据模型（核心实体）

```
Store（门店）
  ├── subdomain, customDomain
  ├── status: active | suspended
  └── commissionRate: 0.10

Product（母库产品/服务）
  ├── type: repair_service | accessory
  ├── brand, model, issueType（维修专用）
  ├── category（配件专用）
  ├── suggestedPrice
  └── status: active | inactive

StoreProduct（门店上架）
  ├── storeId, productId
  ├── price（门店自定义价格）
  ├── depositAmount（维修专用）
  └── isListed: boolean

RepairBooking（维修预约）
  ├── storeId, storeProductId
  ├── customerName, email, phone
  ├── scheduledAt
  ├── status: pending | confirmed | in_progress | completed | cancelled
  ├── depositPaid: boolean, depositAmount
  ├── actualAmount（完成时录入）
  └── commissionAmount（= actualAmount × 0.10）

AccessoryOrder（配件订单）
  ├── storeId, items[]
  ├── customerInfo, deliveryType: shipping | pickup
  ├── totalAmount
  └── status: pending | shipped | ready_pickup | completed

CommissionBill（提成账单）
  ├── storeId, month
  ├── totalRepairRevenue, commissionAmount
  ├── onlineDepositCollected
  ├── offlineAmountDeclared
  └── status: pending | confirmed | settled
```

## 五、技术架构

| 层级 | 方案 |
|------|------|
| 框架 | Next.js 15（App Router），单仓库 |
| 多租户 | hostname middleware → 识别 Store，注入租户上下文 |
| 数据库 | Neon PostgreSQL（Frankfurt） |
| ORM | Prisma |
| 支付 | Stripe（在线定金 + 配件全额支付） |
| 邮件 | Resend |
| 文件存储 | Vercel Blob 或 Cloudflare R2 |
| 部署 | Cloud Run（欧洲 / 美洲 / 亚洲三区域） |
| UI | Tailwind CSS + shadcn/ui，遵循 DESIGN.md |

## 六、开发优先级（建议顺序）

| 阶段 | 内容 |
|------|------|
| Phase 1 | 多租户路由 + 门店页面渲染 |
| Phase 2 | 产品母库 + 门店选品定价 |
| Phase 3 | C 端浏览 + 维修预约（不含支付） |
| Phase 4 | 门店管理端（预约处理 + 内容管理） |
| Phase 5 | Stripe 支付（定金 + 配件） |
| Phase 6 | 配件购物车 + 订单管理 |
| Phase 7 | 财务报表 + 对账功能 |
| Phase 8 | Admin 总部 Dashboard + 数据概览 |
