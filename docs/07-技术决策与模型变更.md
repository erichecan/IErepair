## 一、前端技术决策：Next.js（移动端优先）

### 选型理由

| 方案 | 说明 |
|------|------|
| **Next.js App Router（选定）** | 一套代码覆盖用户端、商家后台、供应商端、管理后台；SSR/SSG 对 SEO 友好；部署简单（Vercel）|
| 原生 App（React Native）| 用户体验最佳，但开发成本翻倍，且 SEO 为零 |
| 纯 SPA（Vite + React）| SEO 差，放弃 |

## 二、Eircode 地理位置方案（无专用服务商）

### 问题背景

爱尔兰 Eircode 是 2015 年引入的 7 位邮编系统（格式如 `D01 AB23`），没有像英国 Postcode 那样成熟的商业解析 API。但有以下几种可行方案。

### 方案对比

| 方案 | 精度 | 成本 | 复杂度 | 推荐度 |
|------|------|------|--------|--------|
| **Google Maps Geocoding API** | 精确到门牌号 | $5/1000次，首200次/天免费 | 低 | ★★★★★ |
| OpenStreetMap Nominatim（免费）| 较好（支持爱尔兰邮编）| 免费 | 低，但有频率限制（1次/秒）| ★★★★ |
| 静态 Eircode 数据库（离线）| Routing Key 级别（约3km²）| 一次性采购 ~€500 | 中 | ★★★ |
| 用户自选地图 Pin | 精确 | 免费 | 中（前端地图 UI）| ★★★ |

### 推荐方案：Google Maps Geocoding API + Redis 缓存

**核心逻辑：**
1. 用户输入 Eircode（如 `D02 XY45`）
2. 后端查询 Redis 缓存，命中则直接返回坐标
3. 未命中则调用 Google Geocoding API：`D02 XY45, Ireland` → `{ lat: 53.3440, lng: -6.2674 }`
4. 将结果缓存到 Redis（TTL：30天，Eircode 坐标基本不变）
5. 用坐标做 PostGIS 距离查询，返回附近门店

**成本估算：**
- 门店注册（一次性解析门店地址）：每家门店 1 次调用，3000 家门店 = 3000 次 = **约 $15 一次性成本**
- 用户搜索：高度缓存复用，假设 50,000 个唯一 Eircode，全部缓存后基本 **$0**
- **实际月成本预估：< $5**

**代码示意（后端）：**
```typescript
async function eircodeToCoords(eircode: string): Promise<{lat: number, lng: number}> {
  const cacheKey = `eircode:${eircode.replace(/\s/g, '').toUpperCase()}`;
  
  // 1. 查缓存
  const cached = await redis.get(cacheKey);
  if (cached) return JSON.parse(cached);
  
  // 2. 调 Google Geocoding
  const res = await fetch(
    `https://maps.googleapis.com/maps/api/geocode/json` +
    `?address=${encodeURIComponent(eircode + ', Ireland')}` +
    `&key=${process.env.GOOGLE_MAPS_API_KEY}`
  );
  const data = await res.json();
  const coords = data.results[0].geometry.location; // { lat, lng }
  
  // 3. 写缓存（30天）
  await redis.setex(cacheKey, 60 * 60 * 24 * 30, JSON.stringify(coords));
  
  return coords;
}
```

**PostGIS 附近门店查询：**
```sql
SELECT 
  m.id, m.shop_name, m.address_line1, m.eircode,
  ST_Distance(m.location, ST_MakePoint($1, $2)::GEOGRAPHY) / 1000 AS distance_km
FROM merchants m
WHERE 
  m.status = 'active'
  AND ST_DWithin(m.location, ST_MakePoint($1, $2)::GEOGRAPHY, $3 * 1000) -- $3 = 半径km
ORDER BY distance_km ASC
LIMIT 20;
-- $1 = lng, $2 = lat, $3 = radius_km
```

### 前端地图展示

- 门店详情页嵌入 **Google Maps Static API**（无交互，便宜）：`$2/1000 次`
- 搜索结果页不显示地图，只显示距离文字（`1.2 km away`）
- 如需交互地图（未来），使用 **Leaflet.js + OpenStreetMap**（完全免费）

## 三、佣金模型修正（与文档 01 不同之处）

### 修正后规则

| 场景 | 资金流向 | 平台是否抽佣 |
|------|----------|-------------|
| **线上购买配件/配件类商品（Stripe）** | 用户 → Stripe → 平台账户 → 月底结算给商家 | **不抽佣**，但平台持有资金后结算 |
| **到店购买配件（刷卡/现金）** | 用户直接付给门店 | **不抽佣，不介入** |
| **线上预约维修（Stripe 预付定金）** | 用户 → Stripe → 平台账户 → 扣除抽佣后结算给商家 | **抽佣**（建议 8~10%）|
| **到店维修（到店付款）** | 用户直接付给门店 | **抽佣**（门店月底通过平台支付应付抽佣）|
| **维修会员购买** | 用户 → Stripe → 平台 → 核销时结算维修费给门店 | 平台从会员费中扣除维修成本后保留利润 |

### 线上配件订单资金流详解

```
用户 Stripe 支付 €29.90（手机壳）
    │
    ▼
Stripe → 平台主账户（IERepair Ltd.）
    │
    ▼
月底结算：
  门店应得 = €29.90 - 支付手续费（约 1.4% + €0.25）
           = €29.90 - €0.67
           = €29.23
    │
    ▼
平台通过 Stripe Connect 转账给门店 IBAN
```

> 平台在配件类商品上**不赚抽成**，但：
> 1. 持有资金 7~30 天（存入账户可产生利息）
> 2. 平台控制退款流程，保护用户体验
> 3. 配件类商品引流带来的维修订单才是主要变现点

## 四、技术栈最终确认

| 层次 | 选型 | 说明 |
|------|------|------|
| 前端框架 | **Next.js 15 App Router** | SSR + API Routes 一体 |
| UI 组件 | **Tailwind CSS + shadcn/ui** | 移动端友好，开发速度快 |
| 数据库 | **PostgreSQL 16 + PostGIS** | 地理位置查询 |
| ORM | **Drizzle ORM** | 轻量、类型安全，与 Next.js 配合好 |
| 缓存 | **Redis (Upstash)** | Serverless 友好，Eircode 缓存、Session |
| 认证 | **NextAuth.js v5** | 支持 Google/Apple OAuth + 自定义 Phone OTP |
| 支付 | **Stripe** | 支持 EUR，Stripe Connect 多方支付 |
| 短信 | **Twilio** | 爱尔兰覆盖好 |
| 地图 | **Google Maps Geocoding API**（后端）+ **Google Maps Static API**（前端展示）|
| 文件存储 | **Cloudflare R2**（兼容 S3，比 AWS 便宜）|
| 部署 | **Vercel**（Next.js 官方，零配置）|
| 数据库托管 | **Neon**（Serverless PostgreSQL，有免费层）|
